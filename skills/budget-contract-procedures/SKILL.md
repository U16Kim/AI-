# 予算要求・財政協議／契約・公募・協定

対象ユーザーは川崎市の課長級職員。お金と契約の判断は、法令と手続の誤りが致命傷になる。**条文・要領・日程・様式は、一次情報で確認できたものだけを事実として書く。確認できないものは「要確認」と書き、確認先を添える。**

## 最初にやること

| モード | 典型的な依頼 |
|---|---|
A 予算要求・財政協議 | 「予算要求資料を作って」「財政にどう説明する」
B 契約・公募 | 「プロポーザルの審査基準」「随意契約にできるか」
C 協定・覚書 | 「官民連携の協定書案」「覚書の骨子」

不足情報は、まとめて1回だけ質問する（最大3項目）。推測できるものは「前提」として明記して進む。

## 共通ルール

- 最初に「概略」を簡単な日本語で、次に詳細を書く。難しい用語には短い注釈を付ける。
- 金額・数量は、積算根拠と時点を付ける。根拠のない数字は書かない。
- 国内外の類似事例を1件以上添える（事業費、体制、契約方式の比較）。
- 作成後は `deliverable-verifier` で数値と論理を検証する。
- 要綱・例規の確認は `rules-research-and-subsidy-drafting`、判断が重い場合は `decision-support` を使う。

## モードA: 予算要求・財政協議

### 手順
1. **要求の型を決める**: 新規／拡充／継続／縮小。補正予算か当初予算か。
2. **日程を確認する**: 要求・協議・査定・議決の時期は年度ごとに変わる。市の最新の予算編成通知で確認する。確認済み（令和9年度予算編成方針、2026-08-24公表）: 11月 オータムレビュー → 12月中旬 内示 → 1月中旬 市長査定 → 2月上旬 公表。出典と他の確認済み事項は `kawasaki-admin-reference` の「予算・財政・計画」。庁内の要求様式・提出期限は未確認なので、財政局の通知で確認する（要確認）。
3. **要求資料の骨子を作る**
   - 事業の目的と、解決する課題（数値で）
   - 事業内容と、積算の内訳
   - 効果（成果指標と目標値、EBPMの考え方で）。投入→活動→産出→成果のつながり（ロジックモデル）を1枚で示す。効果の測り方（比較相手、指標、時期）は、要求の時点で決めておく（`data-science-foundations`）
   - 財源（一般財源・国県支出金・協賛金など）と、将来の財政負担
   - 他の手段（何もしない、縮小、他事業の活用）との比較
   - 国内外の事例
4. **財政協議の想定問答を作る**: 「なぜ今か」「なぜ市が行うのか」「民間でできないか」「他都市は」「効果はどう測るか」「費用が膨らむ要因は」「やめるときの条件は」。
5. **予算の仕組みの論点を洗い出す**
   - 複数年にわたる契約: 債務負担行為（地方自治法第214条）が要るか
   - 年度内に終わらない: 繰越明許費（同法第213条）が使えるか
   - 年度途中の追加: 補正予算（同法第218条）の要否
   - 国の補助金: 内示の時期と、要求時期のずれ
   - 一定額以上の契約、財産の取得・処分: 議会の議決（同法第96条、同法施行令第121条の2と市の条例）が要るか
   - 複数年の契約と物価: 委託料・指定管理料の改定の定め（指標・時期・しきい値）を、仕様と予算の両方に入れるか
   - 長期継続契約（同法第234条の3）で足りるか、債務負担行為が要るか
   条文は e-Gov法令検索で確認してから書く。
6. **財政担当の目で読み直す**: 総額と後年度負担、財源の確かさ、他の手段との比較、やめる条件。金利・物価の前提は、時点と出典を書く（読み方は `startup-corporate-finance` の金融の節）。
7. **弱点チェック**: 効果の根拠が弱くないか、将来負担を小さく見せていないか、財源の見通しが甘くないか。要求の筋（結論→根拠3つ→裏付け）は `logic-storyline` で組む。

### 出力
- 概略（1ページ）／要求資料の骨子／積算表／想定問答／確認事項リスト

## モードB: 契約・公募

### 手順
1. **契約方式の整理**: 原則は競争入札（地方自治法第234条）。随意契約ができる場合は、同法施行令第167条の2に限定されている。**随意契約にしたい場合は、どの号に当たるかを根拠付きで示す。当たらなければ当たらないと書く。**
   - 少額の随意契約（第1号）: 川崎市契約規則第24条の2で額を定めている。確認済みの額は `kawasaki-admin-reference` の「契約・公募」（令和7年6月1日施行の改正後）。使う前に例規集で最新を確認する。
   - 第2号（性質又は目的が競争入札に適しない）: 最高裁の判例がある。`japan-law-research` の判例索引で当たりを付け、判決文を確認してから引用する。「この事業者しかできない」理由を、仕様・実績・権利関係の事実で示す。
   - 見積書: 川崎市契約規則第26条は、随意契約では、なるべく2人以上から見積書を取ると定める。
2. **公募型プロポーザルの設計**（法律に定義はなく、市の運用に従う）
   - 川崎市の確認済みの資料: 「プロポーザルガイドライン」、実施要領の実例（名称は「公募型プロポーザル方式（随意契約）」）、市の実例（官民連携窓口の運営支援プロポーザル）。URLは `kawasaki-admin-reference` の「契約・公募」。起案前に、実例の構成（目的・参加資格・評価項目・配点・審査・契約の扱い）に合わせる。
   - 川崎市版の随意契約ガイドラインは未確認（要確認）。契約規則の随意契約の条文（第24条の2〜第26条）は確認済み。
   - 目的、業務内容、参加資格、スケジュール
   - 評価項目と配点（提案内容、実績、体制、価格）、審査員の構成、利益相反の確認
   - 選定後の契約の扱い（随意契約の根拠）
3. **公平性・透明性のチェック**: 特定事業者に有利な仕様になっていないか。応募期間は十分か。質疑の回答は全員に共有するか。
4. **他都市事例**: 同種の公募の仕様書・審査基準を3件ほど比べる。
5. **事業方式そのものを比べる場合**（委託か、指定管理か、PFIか、貸付か）は、`urban-development-practice` のモードD（スキーム比較表、VFM、リスク分担）を先に行う。
6. **民間提案・実証実験から契約に進む場合**: 提案者・実証の参加者が、本調達で不当に有利にならないか。提案の受付と対話の記録、仕様の中立性、随意契約の根拠を確認する。
7. **確認事項**: 契約担当課、法制、財政への確認事項を一覧にする。

### 出力
- 契約方式の整理表（選択肢と根拠）／仕様書案／審査基準案（配点表）／スケジュール／確認事項リスト

## モードC: 協定・覚書

### 手順
1. 相手方、目的、役割分担、費用負担、期間を整理する。
2. **法的な位置付けを確認する**: 協定は、契約か、紳士協定か。市が義務を負うなら、予算の裏付けと議決の要否を確認する（要確認）。川崎市の官民連携の枠組み（民間活用（川崎版PPP）推進方針、民間活用調整委員会、官民連携総合窓口のテーマ型・フリー型提案）は `kawasaki-admin-reference` の「官民連携」で確認する。提案を受けた事業を協定にする場合は、提案後の対話・選定の記録が残っているかが、公平性の説明の根拠になる。
3. 条項の骨子を作る: 目的／役割分担／費用負担／成果物と知的財産／個人情報・秘密保持／広報・名称使用／事故時の責任／解除・期間・更新／協議条項。
4. **公平性の確認**: 特定の企業だけを優遇しない説明ができるか。公募・対話の過程の記録は残っているか。
5. **方針変更・終了の条件を書く**: 協議の打切り、予算が付かなかった場合、議決が得られなかった場合の扱いを、相手が費用を投じる前に明示する（自治体の方針変更と信頼保護に関する最高裁の判例がある。`japan-law-research`）。
6. **情報公開を前提に書く**: 協定書・提案書は、開示請求の対象になりうる。非公開としたい情報の範囲と理由を、相手と事前に確認する。
7. 法制担当への確認事項を一覧にする。

### 出力
- 協定書の骨子案／条項ごとの論点メモ／確認事項リスト

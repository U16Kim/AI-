# データサイエンスの基礎（手法選択・検証・解釈）

対象ユーザーはデータサイエンティストの資格を持ち、Python・R・SQLを使う自治体課長。目的は、**分析の結論を、反論に耐える形にすること**。数式の説明より、「何を使い、何を確かめ、何を言ってよいか」を示す。

## 最初にやること

| モード | 典型的な依頼 | 読む参照ファイル |

| A 手法を選ぶ | 「どの検定・モデルを使うか」「この設計でよいか」 | `references/method-selection.md` |
| B 効果を測る（因果推論） | 「施策の効果はあったか」「相関か因果か」 | `references/causal-inference.md` |
| C 予測モデルを作る・検証する | 「過学習していないか」「評価指標は」「モデルを説明したい」 | `references/ml-validation.md` |
| D 結果を読む・レビューする | 「この分析は正しいか」「この数字の意味は」 | 3つすべての「落とし穴」の節 |
| E 学び直す | 「〇〇を基礎から」 | 該当ファイル |

## 共通ルール

- 最初に「概略」を簡単な日本語で、次に詳細を書く。**専門用語は使うたびに、かっこ書きで言い換える**（例：交絡〔原因と結果の両方に効く第三の要因〕）。数式は、言葉の説明の後に、必要な場合だけ示す。
- **問いを先に分類する**：記述（何が起きているか）／予測（次に何が起きるか）／因果（何をすれば変わるか）。政策判断の多くは因果の問いであり、予測モデルの結果をそのまま因果として語らない。
- コードは Anaconda（JupyterLab）と Google Colab の両方で動く形で出す。冒頭に「誰が・どのアプリで・何を・どうする」を書き、コードの後に、行ごとの意味を普通の言葉で解説する。R・SQLを求められたら、その言語で書く。
- 結果は必ず「点の値＋幅（信頼区間など）＋効果の大きさ＋前提」の4点で報告する。p値だけで語らない。
- 言えないことを明記する（データの限界、外挿、因果の未確定）。

## A. 手法を選ぶ手順

1. 問いの種類（記述・予測・因果）と、決めたいことを1文で書く。
2. データの形を確認する：分析の単位、件数、目的変数の型（連続・二値・カウント・順序・生存時間）、時間・空間・階層の構造、欠測。
3. `references/method-selection.md` の早見表から候補を2つ選び、**単純な方から**試す。
4. 前提を確かめる（独立性、分布、外れ値、多重共線性）。崩れている場合の代替を示す。
5. 検出力（効果を見つけられる確率）とサンプルサイズを計算する。足りない場合は、そう書く。

## B. 効果を測る手順

1. **反実仮想を言葉にする**：「施策がなかったら、この地域はどうなっていたか」。これが比較相手の設計図になる。
2. 因果の図（DAG）を描き、交絡を洗い出す。
3. 使える識別戦略を、強い順に検討する：無作為化 → 回帰不連続 → 差の差・イベントスタディ → 操作変数 → 合成コントロール → 傾向スコア・二重に頑健な推定 → 単純な回帰。
4. 前提を検証する（平行トレンド、連続性、バランス、プラセボ検定）。
5. 効果の大きさを、政策の言葉に直す（「1施設あたり月〇人増」「費用1万円あたり〇件」）。
6. **感度分析**で、未観測の交絡がどれだけあれば結論が覆るかを示す。

## C. 予測モデルの手順

1. 評価指標を先に決める（業務の損得に合うもの）。
2. データを分ける。**時系列は時間順、空間データは地域のまとまりで分ける**。無作為に分けると、成績が実力より良く出る。
3. 単純な基準モデル（平均、前年同値、ロジスティック回帰）を先に作る。複雑なモデルは、これを上回って初めて意味がある。
4. 交差検証で調整し、最後に手を付けていないテストデータで1回だけ評価する。
5. 説明（特徴量の重要度、SHAP、部分依存）を付ける。ただし、これは「モデルが何を使ったか」であり、因果ではない。
6. 公平性・個人情報・運用後の劣化（データの分布の変化）を点検する。

## D. レビューの点検表（他人の分析・自分の分析）

- [ ] 問いと手法が合っているか（因果の問いに、予測モデルで答えていないか）
- [ ] 分析の単位と、結論を当てはめる単位が同じか（地域の傾向を個人に当てはめる誤り＝生態学的誤謬）
- [ ] 比較相手は妥当か。選ばれ方に偏りがないか（選択バイアス、生存者バイアス）
- [ ] 多数の検定・多数の指標から、都合のよいものだけを選んでいないか（多重比較）
- [ ] 平均への回帰（極端な値は次に平均へ近づく）を、効果と取り違えていないか
- [ ] 集計の区切り方で結論が変わらないか（可変単位地区問題、シンプソンのパラドックス）
- [ ] テストデータの情報が学習に漏れていないか（リーク）
- [ ] 統計的に有意でも、実務上の意味がある大きさか。逆に、有意でないことを「効果なし」と言っていないか
- [ ] グラフの軸・縮尺・母数が誤解を生まないか

## 公共分野での応用の地図

| 行政課題 | 使える手法 | 必要なデータ |
|---|---|---|
| 施策の効果検証（EBPM） | 差の差、合成コントロール、回帰不連続 | 施策前後・対象と非対象の時系列 |
| 需要予測（施設、交通、保育、救急） | 勾配ブースティング、状態空間モデル、階層ベイズ | 利用実績、人口、気象、暦 |
| 施設配置・再編 | 立地配分モデル、到達圏分析、カバー率の最適化 | 施設・人口メッシュ・道路網 |
| 空き家・老朽化の予測 | 分類モデル、生存時間分析 | 建物・水道閉栓・登記・住基の統合 |
| 地価・賃料への影響 | ヘドニック分析、空間回帰、差の差 | 不動産取引価格、地価公示、POI |
| 人流・にぎわいの評価 | 時系列の中断分析、空間統計 | 人流データ、歩行者量調査 |
| 災害リスクと脆弱性 | 空間重ね合わせ、クラスタリング、多基準評価 | ハザードマップ、建物、要配慮者 |
| 住民意見・議事録の分析 | トピックモデル、埋め込みによる分類、LLMによる要約と人手の検証 | 自由記述、会議録 |
| 画像・衛星データ | 画像分類・セグメンテーション、変化検出 | 航空写真、衛星画像、点群（PLATEAU） |
| 政策資源の配分 | 予測と最適化の組合せ、アップリフトモデリング（介入の効きやすい対象を探す） | 過去の介入と結果 |

# 型A・F・E（講演・広報・技術解説）の視覚基準

型A（ビジョン・説得）、型F（祝祭・広報・集客）、型E（技術・分析の解説）は、文字と棒グラフだけでは伝わらない。**全ての面に、内容を説明する視覚要素を置く。** ただし、数で満たすのではなく、質で満たす（枚数の決まりは置かない）。

## 1. 質の基準

| 項目 | 基準 |
|---|---|
| 視覚要素のない面 | 0。全てのスライド・全てのセクションに、図・チャート・画像・主役の活字のいずれかがある |
| 視覚要素の役割 | 1つずつ、「何を説明しているか」を1文で言える。言えないものは装飾であり、外す |
| 概念図 | 仕組み・関係・流れを説明する図を、主要な論点ごとに1つ。型Eでは最重要 |
| チャート | データの性質に合う形を選ぶ（比較・推移・構成・分布・関係・工程）。同じ形を続けない。形と色は `dataviz` |
| 章の切れ目 | 主要なセクションごとに扉を置く。活字で作るのが既定。画像を使うのは、下の「画像の使い方」を満たすときだけ |
| 一貫性 | 色・書体・図の作法・アイコンの線の太さが、全体で同じ |
| 禁止 | 絵文字、内容と関係のない装飾画像、題材からの短絡（AIだから回路、量子だから星雲、都市だから俯瞰写真） |

## 2. 画像の使い方

優先する順に検討する。

1. **依頼者が渡した素材**（実写、図面、現地写真）。最も強い。出典と利用条件を確認する。
2. **データから作る絵**：地図（`urban-basemap-gis`）、人流や分布の可視化、実測値の図。内容そのものが絵になる。
3. **図形と活字で作る概念図**。直せる、印刷に強い。
4. **生成画像（下の技法）**：光・粒子・流れそのものが内容である場合に限る（例：夜間光、人の流れの軌跡、ネットワーク）。雰囲気づくりのためだけには作らない。

型B・C・D・Gには、画像を使わない（`design-system.md`）。

## 3. 生成画像の技法（Python。numpy＋PIL）

画像編集のツールは生成ができず、素材サイトは専門的な題材では見つからないことが多い。内容に必要な絵を自分で描く場合は、数理に基づいて描画する。著作権の心配もない。

```python
# 誰が：作成者（Claude）が／どこで：作業フォルダで／何を：光の線と点の絵を／どうする：重ねて描く
# 1) float32 の加算バッファに「光」を積む
# 2) 背景 = 放射状のグラデーション＋微粒子
# 3) 発光レイヤ = PIL ImageDraw で細い線と点を描く
# 4) にじみ（bloom）= 複数の半径のぼかしを重ねる（必ず縮小してから）
# 5) 仕上げ = 周辺を暗くする＋粒状感
import numpy as np
from PIL import Image, ImageFilter

def f(img): return np.asarray(img, np.float32) / 255.0
def screen(a, b): return 1.0 - (1.0 - a) * (1.0 - b)

def bloom(core_img, passes=((6, .55), (18, .42), (52, .30), (120, .20))):
    W, H = core_img.size; acc = np.zeros((H, W, 3), np.float32)
    for radius, strength in passes:
        k = max(1, int(radius / 5))                       # 縮小してからぼかす（速さのため）
        small = core_img.resize((max(8, W // k), max(8, H // k)), Image.BILINEAR)
        small = small.filter(ImageFilter.GaussianBlur(max(1.0, radius / k)))
        acc = screen(acc, f(small.resize((W, H), Image.BILINEAR)) * strength)
    return acc
```

コードの意味：`bloom` は、光っている部分のまわりに、やわらかいにじみを足す処理。大きな画像をそのままぼかすと数分かかるので、いったん小さくしてからぼかし、元の大きさに戻している。

実行時の注意（過去に踏んだ地雷）：
- にじみは必ず縮小して処理する。元の大きさで半径120のぼかしをかけると、時間切れになる。
- 裏で動かす実行（`nohup ... &`）は、途中で止められる。対象を引数で指定し、3〜4点ずつ分けて実行する。
- 作った後に、全ファイルが壊れていないか確かめる（`Image.open(p).load()`）。中断すると、途中までの画像が残る。
- 一覧（コンタクトシート）を作り、必ず自分の目で見る。安っぽく見えるものは使わない。

## 4. 画像の上に文字を置くとき

可読性のための暗幕を、半透明の四角形の重ね置きで作らない。段差が縞になって見える。**画像そのものに、なめらかな濃淡を掛けて焼き込む。**

```python
def rampH(w, a, b, p=1.0):                 # 左から右へ、明るさを a から b へ変える
    t = np.linspace(0, 1, w, dtype=np.float32) ** p
    return a + (b - a) * t
arr = arr * rampH(w, 0.13, 1.0, 0.75)[None, :, None]   # 左を暗くして、左に文字を置く
```

図形の影・図形のグラデーションは使わない（共通の禁止事項）。画像に焼き込む濃淡は、これに当たらない。

## 5. HTMLの成果物

- **1ファイルで完結させる。** 画像は軽くして（JPEG 品質82、幅1100〜1920px）、base64でファイルの中に埋め込む。外部の読み込みに頼らない。埋め込みの合計は2MB以内が目安。
- **端末がダークでもライトでも読めるようにする。** 地の色と文字の色を、両方とも自分で指定する（片方だけ指定すると、端末の設定で読めなくなる）。地を明るくするか暗くするかは、型と内容で決める。
- スマートフォンの幅で、横にはみ出さない。文字は16px以上。
- 使える構成要素：冒頭の大きな見出しと要点／セクションの扉／図版と論旨を左右に並べる配置（狭い画面では縦に積む）／`figure`＋`figcaption` の図版／SVGで自作したチャート（画面に入ったときに一度だけ動く）／触って確かめられる要素（スライダー、切替えボタン）を、内容の理解に役立つ場合に1つ以上。
- 動きを減らす設定（`prefers-reduced-motion`）に対応し、画面の外では動きを止める。
- 公開するページは `artifact-design` の決まりにも従う。

## 6. PPTXの構成（型A・F・E）

- 表紙と結論は、主役の活字、または上の「画像の使い方」を満たす画像で、全面を使う。
- 主要なセクションごとに扉を入れる（大きな章番号＋章題）。
- 本編は、全面・左右分割・上部の帯・カードを混ぜる。同じ骨格を3枚以上続けない。
- 全スライドに `addNotes()` で台本を入れる。
- 暗い地は、暗い会場で投影し、印刷しない場合だけ。
- 文字の大きさ・色の釣り合いは `design-system.md` の尺度に従う（型A・F・Eでも、尺度と太字の決まりは同じ）。

## 7. 中身の質（視覚と同じ重さの要件）

- 主張 → 図表 → 留保、の順に置く。「ただし、こう読むべき」を添える。
- 数値に出典と時点を付ける。推計・逆算・定性的な評価は、そうと分かるように書く。
- 企業や行政の計画の到達年は、「目標であり、実績ではない」と注記する。
- 川崎市・まちづくり・EBPMへの意味合いを、可能な場合は1セクション設ける。
- 最後は、時間軸ごとの行動（今すぐ／3〜5年／5〜10年）で締める。

## 8. 完成前の点検（型A・F・E）

- [ ] 視覚要素のない面がない。全ての視覚要素について、何を説明しているかを1文で言える
- [ ] 主要な論点ごとに、仕組みを説明する図がある
- [ ] チャートの形が、データの性質に合っている。同じ形が続いていない
- [ ] 画像は「画像の使い方」の順で選んだ。題材からの短絡と、関係のない装飾がない
- [ ] 縞・はみ出し・重なりがない（全頁を描画して目視した）
- [ ] HTMLが1ファイルで完結し、ダークでもライトでも、スマートフォンでも読める
- [ ] 出典と留保が書いてある

# 自治体の都市分析のためのベースマップ作成（行政区域＋OSM）

## 1. このスキルの考え方

地図は「**指標が主役、ベースマップは脇役**」。行政区域の境界・主要な道路・鉄道・水域だけを薄く敷き、その上に政策の指標を載せると、
地域差や施設の偏りが一目で伝わる。逆に、道路や建物を全部濃く描くと、肝心の指標が埋もれる。
そこで、このスキルは次の順で作業する：**①範囲を決める → ②行政区域を取る → ③OSMを取る（一度だけ取って保存）→ ④描く → ⑤QGIS/Tableau用に書き出す**。

OSMや行政区域のデータは、取得に時間がかかり、公開サーバーに負荷もかける。**一度取得したらファイルに保存し、以降は保存したファイルを使う**（コードがこれを自動で行う）。

## 2. 出力ルール（共通）
1. 先に「概略」（簡易な日本語で3〜5行）、次に「詳細」を書く。専門用語には短い注釈をつける。
2. 「誰が・どのアプリで・何を・どうするか」を明記し、GUI操作はクリック順で書く。
3. コードを示したら、内容を必ず解説する。環境は Anaconda/JupyterLab と Google Colab の両方で動く形にする。
4. すべての地図に**出典表記**を入れる（§7）。出典・提供状況が確認できないものは「⚠️要確認」と書く。

## 4. 手順

### ▶ STEP 1：範囲を決める
対象（例：川崎市の7区）を確認する。曖昧なら `AskUserQuestion` で、**単位（区ごと／市まるごと）**と**入れたい要素（道路・鉄道・駅・水域・公園・施設・建物）**を聞く。
自治体コードは5桁（川崎市7区＝14131〜14137、川崎市＝14130、横浜市＝14100、東京都＝13xxx）。区名を使うか、コードの前方一致（`code_prefix="1413"`）で指定する。

### ▶ STEP 2：行政区域を取得して整える
1. あなたが、ブラウザで https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2026.html を開く（年は最新版を選ぶ）。
2. 表の「神奈川県」の行にある `N03-20260101_14_GML.zip` をクリックして保存する（都道府県コード14＝神奈川県）。利用規約に同意するよう求められた場合は内容を確認する。
3. あなたが、次を実行する。

```python
import sys; sys.path.append("scripts")
import basemap as bm

admin = bm.read_n03("data/N03-20260101_14_GML.zip")      # zipのまま読める（Shapefile/GeoJSONを自動で探す）
kawasaki = bm.select_area(admin, code_prefix="1413")     # 川崎市の7区（飛び地は複数行のまま）
kawasaki = bm.dissolve_admin(kawasaki, level="ward")     # 区ごとに1行へまとめる（市全体なら level="city"）
```
- `download_n03()` で自動取得もできるが、実際のダウンロードURLを確認できていないため推定。**失敗したら上の手動手順を使う**（関数が手順を表示する）。
- N03 の属性：都道府県名・郡/政令市名・市区町村名（政令市は区名）・行政区域コード（5桁）。座標系は JGD2011（経緯度）。
- 区域が欠ける・重なるなどの疑いがあるときは、取得ページの「更新履歴」「訂正情報」を確認する（⚠️要確認）。

### ▶ STEP 3：OSMデータを取得して保存する
```python
layers = ["roads", "rail", "stations", "water", "parks"]    # まず軽い基本セット
osm = bm.fetch_osm_layers(kawasaki, layers, cache_dir="data/osm")
```
レイヤーは `OSM_LAYERS` から選ぶ（`roads` 道路／`rail` 鉄道／`stations` 駅／`water` 水面／`waterways` 河川／`parks` 公園／`schools` 学校／`childcare` 幼稚園・保育施設／`hospitals` 病院／`supermarkets` スーパー／`buildings` 建物／`roads_all` 歩行者道を含む全道路）。

| 判断 | 基準と理由 |
|---|---|
| `buildings` を入れるか | **市全域では非常に重く、失敗しやすい**。区ごとの拡大図や、建物密度を指標にしたいときだけ入れる。基本セットには入れない |
| `roads_all` を入れるか | 歩行者導線の分析以外では不要。`roads`（自動車道）で十分に見やすい |
| 取得を区ごとに分けるか | 既定で分ける（`chunk=True`）。大きなポリゴンを1回で問い合わせると、サーバーの制限で失敗するため |
| 再取得するか | 既定では**しない**（キャッシュを使う）。最新に更新したいときだけ `refresh=True` |

**Overpass 公開サーバーの利用方針（OSM Wiki で確認）**：1日あたり1万クエリ未満・1GB未満・処理時間10分以内なら一回限りの利用として許容／並列実行はしない／429・406 が返ったら30秒待つ／`User-Agent` で自己申告する／呼び出しをキャッシュする／**商用利用は自前または有償サーバーを使う**／サーバーは過負荷気味で信頼性は高くないとの注記あり。→ 業務でくり返し・大量に使うなら、OSMの抽出データ（Geofabrik等）をダウンロードして使う方法を検討する（⚠️要確認）。

> **OSMの限界（地図に必ず注記する）**：OSMは有志の入力で、地域・種類によって網羅性が違う。特に保育施設・学校などの**施設数を集計して指標にする**場合は、OSMの件数を鵜呑みにせず、自治体のオープンデータ（公式の施設一覧）と照合する。OSMは「位置を見せる補助」として使い、「公式な件数」の根拠にしない。

### ▶ STEP 4：描く
```python
fig = bm.draw_basemap(kawasaki, osm, title="川崎市 ベースマップ", save_path="output/basemap.png")
```
統計を塗り分けるとき：
```python
joined = bm.join_stats(kawasaki, df_stats, stats_code_col="自治体コード")      # 6桁コードも自動で5桁に直す
fig = bm.plot_choropleth(joined, "待機児童数", osm, title="区別 待機児童数",
                         k=4, fmt="{:,.0f}", save_path="output/choropleth.png")
bm.plot_points(fig.axes[0], osm["schools"], bm.pick_local_crs(joined), label="学校")   # 施設の点を重ねる
```
**デザイン指針（理由つき）**
- 階級は**3〜5**。区が7つしかないのに10階級に分けても意味がない。`classify` の既定は分位数（各階級の数が同じ）。値の幅で見せたいなら `scheme="equal"`、基準値がある指標（国の目標値など）は `bins=[...]` で指定する。
- 凡例は**数値の範囲を「以上・超・以下」で明記**する（階級の切り方で印象が変わるため）。
- 欠損・秘匿は**灰色の「データなし」**で示す。0と混ぜない。
- 面積・距離を測るときは投影座標系を使う。`pick_local_crs()` が、首都圏4都県は平面直角座標系Ⅸ系（EPSG:6677）、それ以外は UTM を推定して選ぶ（後者は⚠️精密な面積計算には座標系の確認が必要）。
- 人数の「実数」で塗ると、人口の多い区が高く出るだけになりやすい。**率（人口あたり・世帯あたり等）**で塗るのが原則。実数で塗るときは、その旨を図の注記に書く。
- スマホ表示や印刷では、文字は9pt以上、ベースマップの線は細く薄くする。

### ▶ STEP 5：QGIS・Tableau 用に書き出す
```python
paths = bm.export_layers({"admin": joined, **osm}, "output/gis", "kawasaki")
```
| 出力 | 使い方 |
|---|---|
| `kawasaki.gpkg` | QGIS で全レイヤーをまとめて読み込む（GeoPackage。操作手順は `references/qgis-clickflow.md`） |
| `kawasaki_admin.geojson` | Tableau で行政区域を読み込む（⚠️ Tableauの対応形式は版により異なる。読めなければ Shapefile で書き出す） |
| `kawasaki_admin.csv` | 属性＋中心点の経度・緯度。Tableau・Excel で点として使う |

## 5. policy-data-workflow との連携
- STEP04（データ検索）で空間データが要るとき → このスキルの STEP2〜3 を実行し、`data/` に保存する。
- STEP09（可視化）・STEP10（空間分析）→ `join_stats` で統計を結合し、`plot_choropleth` で地図化する。モランI（空間的な偏りの検定）は policy-data-workflow の `morans_i` に、`kawasaki`（行政区域）と指標列を渡す。
- 結合キーは**5桁の自治体コード**。e-Stat 等の6桁コードは `to_jis5()` で先頭5桁に直る。結合できなかった区域は関数が警告する（合併・区の新設・コード体系の違いが原因のことが多い）。

### 統計としての注意（地図は誤解を生みやすい）
- 塗り分け地図は、**実数ではなく率・密度**で描く（人口の多い区が濃くなるだけの地図を避ける）。実数は、円の大きさで示す。
- 階級の区切り方（等間隔・分位・自然分類）で印象が変わる。区切りの方法を凡例に書き、別の区切りでも結論が変わらないかを見る。
- 集計単位（区・町丁・メッシュ）を変えると傾向が変わることがある。区単位の傾向を、個々の住民に当てはめない。
- 距離・面積は投影座標系（関東は EPSG:6677）で測る。到達圏は、直線距離ではなく道路網で測る。
- 手法の選び方と空間統計の読み方は `data-science-foundations`、色・凡例の設計は `dataviz`、資料への載せ方は `kmr-visual-deliverables`。

## 6. よくある失敗と対処
| 症状 | 原因と対処 |
|---|---|
| OSM取得が途中で失敗する | 区が大きい・レイヤーが重い。`chunk=True` のまま、`buildings` は後回しにして1レイヤーずつ取得する。429/406 は30秒待つ（コードが再試行する） |
| 地図の文字が □ になる | 日本語フォント未設定。`pip install matplotlib-fontja` |
| 川崎区の島（東扇島等）が別ポリゴンで出る | 正常（飛び地）。`dissolve_admin` で区ごとに1行にまとめる |
| 統計が結合できない | コードが数値で先頭0が落ちている／6桁／区と市の粒度違い。`join_stats` の警告を見る |
| 面積が極端にずれる | 経緯度のまま面積計算している。`pick_local_crs()` の座標系に変換してから計算する |

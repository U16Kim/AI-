# 技術士（建設部門：都市及び地方計画）／データサイエンティスト

条番号・制度の細部は覚え書き。使う前に、e-Gov法令検索、日本技術士会、文部科学省、各団体の公表資料で確認する。

## A. 技術士

### 責任と名称（技術士法）

| 事項 | 要点 |
|---|---|
| 性格 | 名称独占の資格（業務独占ではない）。科学技術に関する高等の専門的応用能力を必要とする事項の計画・研究・設計・分析・試験・評価と、その指導 |
| 3つの義務 | 信用失墜行為の禁止／秘密保持義務（技術士でなくなった後も）／名称表示の場合の義務（登録を受けた技術部門を明示する） |
| 2つの責務 | 公益確保の責務（公共の安全、環境の保全その他の公益を害さない）／資質向上の責務（継続研さん） |
| 名称の書き方 | 「技術士（建設部門）」のように、登録部門を必ず書く。選択科目は「都市及び地方計画」 |
| 継続研さん（CPD） | 日本技術士会が、実績の登録・証明のしくみを運用している。目標時間や区分は、同会の最新の案内で確認 |
| 倫理 | 日本技術士会の技術士倫理綱領。公衆の安全・健康・福利の最優先、持続可能な社会、信用の保持、有能性の重視、真実性の確保、公正かつ誠実な履行、秘密情報の保護、法令等の遵守、相互の尊重、継続的な資質向上（項目と文言は最新版で確認） |

**公益確保の責務と、組織の指示がぶつかる場面**が、技術者倫理の中心。公務員の場合は、法令遵守義務・上司の命令に従う義務・守秘義務との関係を整理し、組織内の手続（上申、記録、内部通報）を先に使う。

### 資質能力（コンピテンシー）の8項目

専門的学識／問題解決／マネジメント／評価／コミュニケーション／リーダーシップ／技術者倫理／継続研さん。

所見や提言を書くときの点検にも使える：

| 項目 | 自分への問い |
|---|---|
| 問題解決 | 課題を複数の観点から挙げ、最も重要なものを選んだ理由を言えるか。複数の解決策を比べたか |
| 評価 | 提案した策を実行した後に生じうるリスクと、その対策まで書いたか |
| マネジメント | 人員・予算・工程・品質の制約の中で、資源の配分を示したか |
| 技術者倫理 | 公衆の安全と、将来世代・環境への影響を確かめたか |
| コミュニケーション | 専門でない相手に、誤解なく伝わる書き方か |

### 技術士としての所見の型（課題解決型）

1. 現状と背景（データで）
2. 課題を、複数の観点（技術・制度・財政・人材・合意形成など）から3つ程度挙げる
3. 最も重要な課題を1つ選び、理由を述べる
4. 解決策を複数示す（それぞれの効果と条件）
5. 解決策を実行しても残るリスク、新たに生じる懸念と、その対策
6. 技術者倫理と社会の持続可能性の観点から、守るべきこと

この型は、政策提言や幹部説明の骨格にそのまま使える（`logic-storyline`）。

## B. データサイエンティスト

「データサイエンティスト」は、単一の国家資格の名称ではない。保有している資格・検定の正式名称（例：データサイエンティスト検定、統計検定、G検定・E資格、情報処理技術者試験の区分など）を、提案書や名刺では正確に書く。**正式名称は本人に確認する。**

### 3つの力（データサイエンティスト協会の整理）

| 力 | 内容 | 自治体実務での現れ方 |
|---|---|---|
| ビジネス力 | 課題を定義し、分析を意思決定につなげる | 政策課題を「データで答えられる問い」に直す。結果を幹部・議会の言葉に直す |
| データサイエンス力 | 統計、機械学習、最適化などを理解して使う | 手法の選択、検証、限界の説明（`data-science-foundations`） |
| データエンジニアリング力 | データを集め、整え、使える形で実装・運用する | オープンデータの取得、庁内データの統合、SQL・GIS・ダッシュボード |

スキルの項目は、同協会のスキルチェックリストとタスクリストが定期的に改訂されている。生成AIに関する項目も追加されているため、最新版で棚卸しする。

### 更新すべき論点

| 領域 | 論点 |
|---|---|
| 統計・因果推論 | 導入時期がずれる施策の差の差の新しい推定量、二重機械学習、感度分析、ベイズ推定の実務利用 |
| 機械学習 | 表形式データでの勾配ブースティングの位置、コンフォーマル予測、確率の較正、基盤モデルの転用 |
| 生成AI | 大規模言語モデルの評価方法、検索拡張生成（RAG）、エージェント、プロンプトと出力の記録、幻覚（もっともらしい誤り）への対策 |
| データ基盤 | Parquet・DuckDB・Polarsなどの軽量で速い道具、dbt、クラウドのデータ基盤、地理空間のクラウド最適化形式（GeoParquet、COG、PMTiles） |
| 空間データ | PLATEAU、人流データ、衛星データ、不動産情報ライブラリ、メッシュ統計 |
| ガバナンス | 個人情報保護法（行政機関等の規律）、AI事業者ガイドライン、AIに関する国内法（令和7年に成立した人工知能関連技術の研究開発及び活用の推進に関する法律）、EUのAI規則、著作権と学習データ、自治体の生成AI利用ガイドライン |
| 倫理 | 公平性、説明可能性、プライバシー、自動化された判断への人の関与 |

### 行政のデータ分析で守ること

- 目的外利用をしない。庁内データを使うときは、根拠（法令・条例・同意）を確認する。
- 少数のセルから個人が分かる集計を出さない。
- 分析の再現に必要な情報（データの時点、処理の手順、コード、版）を残す。
- 結果の限界を、結論と同じ場所に書く。

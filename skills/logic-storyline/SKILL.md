# 論理構成とストーリー設計

良い資料は、作る前に勝負が決まっている。**結論が1文で言えず、根拠が3つに絞れず、読み手の疑問に答える順に並んでいない資料は、どれだけ見た目を整えても通らない。** このスキルは、見た目に入る前の設計図を作る。

精緻な論理（正しさ）と、人を惹きつける流れ（伝わり方）は、別の技術。前者だけでは読まれず、後者だけでは信用されない。両方を、この順で設計する。

## 手順

### Step 1：場面を決める（3つの問い）
- **誰が読む（聞く）か**：役職、知識、関心、懸念、この件への立場（賛成・中立・反対）。
- **読んだ後、何をしてほしいか**：決裁／了承／方針の選択／協力／理解／行動。これが **Ask**。
- **どこで、どれだけの時間で**：対面の説明か、回覧か、投影か。3分か、30分か。

Askが1文で書けないうちは、先へ進まない。不足情報は、まとめて1回だけ聞く（最大3項目）。

### Step 2：問いを立てる
読み手が抱く中心の問いを、1つの疑問文にする。SCQの型を使う：
- **S 状況**：読み手が既に同意している事実。
- **C 変化・障害**：その状況を揺るがす出来事、放置した場合の不都合。
- **Q 問い**：そこから自然に出る疑問（「では、どうすべきか」「どの案を選ぶか」「なぜ今か」）。

問いの立て方で、資料の8割が決まる。問いが広すぎると、結論がぼやける。

### Step 3：結論を先に言い切る
問いへの答えを、**主語と述語のある1文**で書く。「〜について」は結論ではない。数字と期限を入れる。まだ根拠が弱くても、仮の結論を置き、後で検証して直す（仮説から始める）。

### Step 4：ピラミッドを組む
```
結論（Askを含む1文）
├─ 根拠1 ── 裏付け（データ・事例・法令）
├─ 根拠2 ── 裏付け
└─ 根拠3 ── 裏付け
```
- 根拠は3つ以内。漏れと重なりがないか（切り口をそろえる）。
- 上から下へ「なぜそう言えるか」、下から上へ「だから何か」が、どの段でも通ること。
- 並べ方は2通り：**並列型**（独立した理由を並べる。1つ崩れても残りが支える）と、**解説型**（事実→判断基準→結論。筋は強いが、1か所崩れると全体が倒れる）。反対が予想される場面は、並列型が安全。
- 詳しい道具は `references/logic-tools.md`。

### Step 5：攻められる所を先に潰す
- 各根拠に、**最も強い反論**を1つ立てる。答えられなければ、根拠を直すか、結論を弱める。
- 論証の型で点検する：主張／データ／**論拠（データがなぜ主張を支えるかという、隠れた前提）**／裏付け／限定（どの範囲で成り立つか）／反証（成り立たない条件）。隠れた前提が、最も攻められる。
- 「やらない場合」「延期する場合」「別の案」と比べたか。
- 事実・推測・意見が分かれているか。数字に出典と時点があるか。
- 誤りの型（`references/logic-tools.md` の一覧）に当たっていないか。

### Step 6：流れを設計する（惹きつける）
論理の順と、伝える順は違ってよい。読み手の頭の中の疑問が生まれる順に並べる。
- **冒頭30秒**：結論とAsk。忙しい読み手は、ここで読むかどうかを決める。
- **緊張を作る**：現状と、あるべき姿の差。数字1つ、または当事者の具体的な場面1つで示す。差が感じられないと、解決策は響かない。
- **山場を1つ決める**：最も伝えたい1枚（1節）。そこに最も強い証拠と、最も大きな余白を使う。全部を強調すると、何も残らない。
- **疑問に先回りする**：「費用は」「他都市は」「リスクは」「なぜ今か」が出る順に答える。
- **締め**：Askを繰り返し、次の一歩（誰が、何を、いつまでに）で終える。
- 型の選び方と、惹きつける技法は `references/story-patterns.md`。

### Step 7：タイトルに落として、通読で確かめる
- 各スライド・各節の見出しを、**結論の文**で書く（名詞止めにしない）。
- 見出しだけを上から読んで、話が通るか（通読テスト）。通らなければ、構成に穴がある。
- 1スライド・1段落に、言いたいことは1つ。

### Step 8：設計図を出力する

```
1. 場面（読み手／Ask／場と時間）
2. 問い（S・C・Q）
3. 結論（1文）
4. ピラミッド（根拠3つと裏付け。裏付けの状態：確認済／未確認／要調査）
5. 想定される反論と答え
6. 構成案（見出し＝結論の文。山場に印）
7. 足りない材料（集めるべきデータ・事例・確認事項）
8. 30秒版の台本
```

ここまでを先に示し、了承を得てから、本文・スライドの作成に進む。

## 既にある資料・文章を直すとき

1. 見出しだけを抜き出し、通読テストをする。
2. 結論・根拠・裏付けを、ピラミッドに書き起こす。**書き起こせない所が、論理の穴。**
3. Step 5 の点検を行う。
4. 指摘は「どこが／なぜ弱いか／どう直すか」の3点で示す。直した構成案を付ける。
5. ユーザーの主張に矛盾や甘さがあれば、遠慮なく指摘する。追認だけの構成レビューに価値はない。

## 共通ルール

- 最初に「概略」を簡単な日本語で、次に詳細を書く。
- 論理を整えるために、事実を曲げない。裏付けのない根拠は「未確認」と表示し、集める方法を書く。
- 惹きつけるための誇張をしない。行政の資料では、誇張は信用を失う。強さは、具体性（数字、固有名、場面）から出す。
- 国内外の事例を、根拠の裏付けに使う（成功と失敗の両方）。
- 専門用語は、読み手が使う言葉に置き換える。

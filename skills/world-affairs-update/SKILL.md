# 世界情勢ノートの週次更新

Obsidian Vault の `世界情勢/` フォルダを、Notion「📰 ニュースアーカイブ｜日次まとめ」DB の差分から更新する。

## 設計思想（これを外すと運用が壊れる）

日次ニュースは**出来事**、`世界情勢/` の32ノートは**構造**。粒度が違うため、日次ニュースを構造ノートに直接追記してはならない。半年で「読めない蓄積」に戻る。

そこで2層に分ける。

| 層 | 頻度 | 中身 | 書き込み先 |
|---|---|---|---|
| 定点観測 | 週次 | 10指標の実測値を1行追記＋トリガー判定 | `50_定点観測.md` |
| 構造ノート | トリガー発火時のみ | 提案 → **ユーザー承認** → 反映 | `01`〜`43` ／ 記録は `99_更新ログ.md` |

**「更新しない」判断ができることがこの仕組みの価値。** トリガーが発火しない週は、表に1行足して終わらせる。無理に構造ノートを触らない。

## 前提となる場所

- Obsidianフォルダ：ユーザーが接続した Obsidian Vault 内の `世界情勢/`（未接続なら `mcp__cowork__request_cowork_directory` で接続を依頼）
- Notion DB：`collection://05cae00a-bbb3-40b5-ad02-565e2f8ac722`（「ニュースアーカイブ DB」）
  - 主要カラム：`date:日付:start` / `カテゴリ`（国際情勢・世界経済・日本金融市場・首都圏・川崎・政策・行政・テクノロジー・AI・総合）/ `重要度` / `見出し一覧` / `詳細サマリー` / `出典・参考URL` / `川崎市への示唆`

## 手順

### Step 1｜前回更新日を特定する

`50_定点観測.md` の週次ログ表の**最終行の日付**を読む。これが差分の起点。

### Step 2｜Notionから差分を取得する

`mcp__d0014def-...__notion-query-data-sources` を SQL モードで実行。

```sql
SELECT date("date:日付:start") d, "カテゴリ" cat, "重要度" imp, "見出し一覧" h, "詳細サマリー" s, "出典・参考URL" u
FROM "collection://05cae00a-bbb3-40b5-ad02-565e2f8ac722"
WHERE date("date:日付:start") > '<前回更新日>'
ORDER BY d
```

件数が多い場合はカテゴリを分けて複数回に分割する（1回のレスポンスが大きすぎると欠落する）。

### Step 3｜10指標を抽出する

`50_定点観測.md` の「指標の出典」表に従い、**一次情報優先**で値を取る。Notionに載っていなければ WebSearch で一次情報を当たる。

① ホルムズ通航隻数 ／ ② 戦争保険料率（定量が取れなければ「高止まり／低下」の定性で可）／ ③ Brent原油 ／ ④ 米CPI・PCEコア ／ ⑤ FF金利と次回会合の織り込み ／ ⑥ 日銀政策金利 ／ ⑦ ドル円 ／ ⑧ 日本10年国債利回り ／ ⑨ FAO世界食料価格指数 ／ ⑩ SOX指数

**厳守事項**

- 取れない指標は `n/a` と書く。**推測で埋めない**
- **速報値を使わない。確定値のみ**（Notionアーカイブには日経平均の高安を取り違えた実例がある）
- 日経平均・ダウの日次終値は表に入れない
- 「地政学リスク○/10」のような生成AI由来のスコアは**絶対に入れない**

### Step 4｜週次ログに1行追記する

`50_定点観測.md` の週次ログ表の**末尾**に1行足す（時系列順、最新を下に）。トリガー判定欄に ○／× を入れる。

### Step 5｜トリガーを判定する

| ID | 条件 | 発火時に書き換えるノート |
|---|---|---|
| **A** | ホルムズ通航が平時（135隻/日）の50%以上に回復、**かつ**戦争保険料率が低下 | `30` `14` `24` `01` ＋全ノートの前提見直し |
| **B** | FRBが**実際に利上げ**（据え置き・示唆ではなく実行） | `13` `34` `20` `42` |
| **C** | SOX指数が直近高値からさらに20%下落、**かつ**大手ITが設備投資計画を下方修正 | `16` `33` `12` |
| **D** | 一次情報レベルの制度変更（法成立・閣議決定・政策金利変更・関税の根拠法変更） | 該当ノート |

いずれも発火しなければ **Step 4 で終了**。「今週はトリガーなし。定点観測に1行追記した」とだけ報告する。

### Step 6｜発火した場合：修正案を提示して承認を得る

**自動で構造ノートを上書きしてはならない。** 次の形で提示し、承認を待つ。

```
【トリガーX 発火】
きっかけ：<何が起きたか>（出典URL）
変わる前提：これまで「〜」と書いていた → 「〜」に変える
修正案：
  - [[ノート名]] の「〜」節
    現在：<引用>
    修正後：<新しい文>
```

承認後に反映し、`99_更新ログ.md` に記録フォーマットどおり追記する。

### Step 7｜報告

- トリガーなし：1〜2行で終わらせる。冗長な要約は書かない
- トリガーあり：発火IDと、変わった前提を3行以内で

## 記法（既存Vaultに合わせる）

- YAML frontmatter：`title` / `tags` / `updated` / `status`
- `[[Wikilink]]` で相互リンク。リンク切れを作らない
- callout：`> [!abstract]` `> [!note]` `> [!warning]` `> [!danger]`
- 数字には必ず出典と公表日をセットで書く。書けない数字は書かない
- 「推計」「予想」「観測」と「公表値」を文言で区別する

## 品質ルール（`41_情報源とデータ品質メモ.md` に準拠）

| 階層 | 内容 | 扱い |
|---|---|---|
| S | 一次情報（IMF/日銀/FRB/各省の公表文書・大臣会見録・法令） | そのまま使う。出典URL必須 |
| A | 大手報道機関で複数社が一致 | 「〜と報じられた」と書く |
| B | 大手報道1社／シンクタンクの分析 | 発表主体を明記 |
| C | 個人まとめサイト（note等）・二次集約メディア | 原則使わない。使うなら「要一次確認」と明示 |
| X | 生成AIが付けたスコア・推計値 | **使わない** |

同じ指標を複数のノートに書かない。数字は `50_定点観測.md` にだけ書き、他はWikilinkで参照する。

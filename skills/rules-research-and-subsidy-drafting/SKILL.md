# 例規調査・他都市比較・補助金等の制度設計

法令・行政に関する内容は、正確さが最優先。**条文・様式・日付は、一次情報で確認できたものだけを事実として書く。** 確認できないものは「要確認」と書き、確認方法を添える。

## 最初にやること

依頼をモードに振り分ける。

| モード | 典型的な依頼 |
|---|---|
A 例規調査・適用 | 「この事業に関係する条例・要綱は」「この使い方は許されるか」
B 他都市事例の調査・比較 | 「他都市はどうしているか」「川崎市との違いは」
C 補助金等の要綱・様式・事務フロー策定 | 「交付要綱案を作って」「様式と流れを整理して」

複数にまたがる場合は A → B → C の順に進める（先に使える枠組みを確認し、次に事例を見て、最後に設計する）。

## 共通ルール

- 最初に「概略」を簡単な日本語で、次に詳細を書く。難しい法律用語には短い注釈を付ける。
- 出典（条文番号・URL・取得日）を必ず付ける。
- 例規は改正される。施行日と、確認した日を書く。
- 川崎市の例規は川崎市公式サイトの例規集で確認する。国の法令はe-Gov法令検索（https://laws.e-gov.go.jp/）で確認する。URLはその都度検索で確かめ、記憶で書かない。確認済みの川崎市の資料（補助金規則、要綱の実例、プロポーザル、長期継続契約要綱など）のURLと確認日は `kawasaki-admin-reference` にある。引用する前に、原文で最新性を再確認する。川崎市例規集のURLと、財務規則の条文は未確認なので、その都度検索する（契約規則の随意契約の条文は `kawasaki-admin-reference` に確認済みの内容がある）。
- 国の法令の調べ方、判例の確認、引用の書き方は `japan-law-research` に従う。判例は、判決文を確認できたものだけを書く。
- 東京都・横浜市の例規・制度は `metro-gov-reference` の入口から調べる。
- 最終判断は所管課・法制担当への確認が必要な論点を、「確認事項リスト」として必ず出す。
- 政策・制度の設計では、国内外の事例を必ず示す。

## モードA: 例規調査・適用

### 手順
1. **事実を整理**: 何を、誰が、誰に対して、いくらで、いつ、どこで行うか。
2. **法令の階層で候補を洗い出す**
   - 法律（地方自治法、個別法など）
   - 政令・省令
   - 条例・規則
   - 要綱・要領・通知（行政の内部基準）
3. **一次情報で検索**: 川崎市例規集、e-Gov、所管省庁の通知。複数のキーワードで検索する。
4. **当てはめ表**を作る。

| 根拠 | 要件 | 本件の事実 | 判定（該当／非該当／要確認） |
|---|---|---|---|

5. **グレーな論点**を明示し、「どちらの解釈がより妥当か」と根拠を書く。結論の確度（明確／有力／争いあり／不明）を付ける。
   - 要綱は内部基準であり、住民に義務を課す根拠にならない。義務付け・権利の制限が要るなら、条例の要否を検討する（地方自治法第14条第2項）。
   - 争われ方を見立てる: 審査請求、取消訴訟、住民監査請求・住民訴訟（違法・不当な財務会計行為）。
6. **確認事項リスト**: 誰に（所管課・法制・財政・外部）、何を、いつまでに確認するか。
7. 川崎市議会での過去の質疑・答弁が参考になる場合は、`kawasaki-council-minutes-search` で調べる。

### 注意すべき代表的な論点（例）
- 補助か、負担金か、委託か、協賛か。性質で適用される規定と手続が変わる。
- 公有財産・公共空間の使用は、許可・契約の種類で手続が違う（公共空間の活用は `public-space-unlock` も参照）。
- 屋外広告物、道路、公園、河川など、場所に応じた個別の規制。
- 公平性・透明性・利益相反。特定の民間事業者に有利にならないか。

### 出力
- 概略（結論と確度）
- 当てはめ表
- 確認事項リスト
- 出典一覧（条文・URL・確認日）

## モードB: 他都市事例の調査・比較

### 手順
1. 比較の目的を決める（制度の新設、見直し、議会対応、幹部説明のいずれか）。
2. **比較軸を決める**: 目的、対象、内容、規模（補助率・上限額など）、期間、手続、実績、評価、課題、根拠となる例規。
3. **対象都市を選ぶ**
   - 政令指定都市（特に横浜市、東京都、近隣都市）
   - その分野の先進自治体
   - 海外事例（必要に応じて）
   選んだ理由を1行で書く。
4. **一次情報で調べる**: 各自治体の公式サイト、要綱・要領のPDF、議会の会議録、報告書。報道・ブログは補助に使う。
5. **比較表**を作る。取得日と出典URLを各行に付ける。
6. **川崎市との差分**を整理し、示唆を出す: 採用する／修正して採用する／採用しない。理由も書く。
7. 見つからなかった情報は「確認できず」と書く。想像で埋めない。

### 弱点チェック
- 人口・財政・産業が違う都市を、そのまま比較していないか。
- 制度の「名前」だけでなく、実際の運用（実績・課題）を見たか。
- 成功事例だけを集めていないか（失敗・縮小・廃止の事例も探す）。

### 出力
- 概略（3行）
- 比較表
- 川崎市への示唆（採否と理由）
- 出典一覧

## モードC: 補助金等の要綱・様式・事務フロー策定

### 手順

**1. 制度の位置付けを確認する（先にモードAを行う）**
- 補助・助成・負担金・委託のどれか。公益上の必要性をどう説明するか（地方自治法第232条の2。補助金の公益性は、住民訴訟で繰り返し争われている。判例は `japan-law-research` の索引から確認する）。
- 交付決定の性格（行政処分として構成するか、贈与契約として構成するか）で、不服申立て・取消し・返還の扱いが変わる。川崎市の補助金規則と既存要綱の書きぶりに合わせる。
- 予算科目と、根拠となる川崎市の既存ルール。確認済み: 川崎市の補助金規則（平成13年川崎市規則第7号、最終改正は令和元年規則第53号）が上位にあり、要綱はこの規則を引用して作られている（実例のURLは `kawasaki-admin-reference` の「補助金・要綱」）。この規則の本文では、加算金・延滞金の年率（10.95%）は確認できたが、立入検査と様式の規定は確認できなかった。立入検査・様式・事務フローは要綱側で補う設計になる。規則の最新条文と正式名称は原文で再確認する（要確認）。
- 要綱で運用してよいか、条例・規則が必要か。

**2. 設計項目を決める**（案と代替案を示す）

| 区分 | 検討項目 |
|---|---|
| 目的・対象 | 目的、対象者、対象事業、対象外 |
| 金額 | 対象経費、補助率、上限額、予算額、概算払の可否 |
| 手続 | 公募方法、申請期間、審査基準と体制、交付決定、変更、中止 |
| 事後 | 実績報告、額の確定、請求・支払、検査 |
| 適正化 | 返還、交付決定の取消し、財産処分の制限、書類保存、暴力団排除、個人情報 |
| 評価 | 成果指標（KPI）、効果検証の方法、見直し時期（終期の設定）。効果検証を後で行えるよう、交付前のデータ取得と、比較相手の取り方を要綱・様式に組み込む（`data-science-foundations` の因果推論） |

**3. 様式を作る**
申請書、事業計画書、収支予算書、交付決定通知書、変更・中止申請書、実績報告書、請求書、確定通知書など。各様式に「記載例」と「添付書類」を付ける。

**4. 事務フローを作る**
申請から確定・支払までを図にする。各工程に、担当、標準日数、決裁区分、使う様式を付ける。

**5. リスクを点検する**
二重交付、不正受給、特定事業者への偏り、審査の公平性、事務負担、予算超過、年度またぎ。

**6. 他都市の要綱と比較する**（モードB）。

### 出力
- 要綱案（条文形式。「趣旨」から「附則」まで。条文の書き方は川崎市の既存要綱に合わせる）
- 様式案
- 事務フロー図
- 設計の根拠メモ（なぜこの補助率・上限なのか）
- 想定問答（議会・財政・関係課から出る質問）
- 確認事項リスト

Wordで出す場合は、本文10.5pt以上、見出しは階層ごとに大きくする。作成後は `deliverable-verifier` で検証する。

# 判断フレームワーク・カタログ

判断の型ごとに使えるフレームワークを列挙する。1〜3個選び、判断に効くものだけ使う。各項目は「いつ使うか／やり方／注意」の順。

## 選択型（複数案から選ぶ）

### 加重スコアリング（意思決定マトリクス）
- **いつ**: 選択肢が2つ以上あり、評価軸が複数あるとき。選択型の基本形
- **やり方**: ①判断基準を3〜6軸に整理 ②各軸に重み（合計100）③各案を軸ごとに1〜5点で採点 ④加重合計で順位付け ⑤**重みを±10〜20動かして順位が入れ替わるか感度分析**
- **注意**: 採点根拠を必ず言語化する。点数だけ並べると恣意的に見える。感度分析で結論が揺れるなら確度を下げて報告

### 期待値・ペイオフマトリクス
- **いつ**: 結果が不確実で、シナリオごとの損得が金額や数値で見積もれるとき
- **やり方**: シナリオ（好調/標準/不調など）×選択肢の表を作り、各セルの損得×発生確率で期待値を計算
- **注意**: 確率の根拠を明記。行政では「最悪ケースの許容可能性」が期待値より重視されることが多い（ミニマックスと併用）

### 一対比較（簡易AHP）
- **いつ**: 評価軸の重み付け自体に迷うとき、関係者間で重みの合意が要るとき
- **やり方**: 軸同士を一対で比較し（どちらがどれくらい重要か）、そこから重みを導出してから加重スコアリングへ
- **注意**: 完全なAHPは重い。3〜5軸の簡易版で十分

## 採否型（やるか、やらないか）

### 費用便益・費用対効果
- **いつ**: 事業・制度の新設や投資の採否
- **やり方**: 定量化できる費用と便益を列挙して比較。定量化できない便益は別枠で明示（無理に金額換算しない）
- **注意**: 「やらない場合のコスト」（機会損失、課題放置の悪化分）を必ず入れる。初期費用だけでなく運用費用（人件費・兼務負荷含む）を含める

### プレモーテム（事前検死）
- **いつ**: 採用に傾いているとき、その熱を一度冷ますために
- **やり方**: 「1年後、この事業は失敗した」と仮定し、失敗理由を5つ挙げる。各理由の発生確率と予防策を検討
- **注意**: 失敗理由が「潰せる」ものばかりなら採用の確度が上がる。潰せない構造的理由が出たら立ち止まる

### リバーサルテスト・機会費用
- **いつ**: 現状維持と新規案で迷うとき
- **やり方**: 「もし現在すでに新規案を実施していたら、やめて現状に戻すか？」と問う。戻さないなら現状維持バイアスの疑いが強い
- **注意**: 投入する人員・予算・時間で「代わりに何ができたか」も一言添える

## 優先順位型（資源配分）

### 重要度×緊急度（アイゼンハワー）
- **いつ**: タスク・案件の仕分け。軽い判断向き
- **やり方**: 2×2に配置し、「重要だが緊急でない」領域の保護を最優先に考える
- **注意**: 全部「重要かつ緊急」に見えるときは、影響の不可逆性で切り直す

### RICE / ICE スコア
- **いつ**: 施策・事業候補が多数あり、限られた予算・人員で順番を決めるとき
- **やり方**: Reach（影響人数）×Impact（効果）×Confidence（確度）÷Effort(工数)でスコア化
- **注意**: 行政ではReachに「政策的重要性（総合計画との整合）」の軸を足すとよい

### パレート分析
- **いつ**: 課題や需要が分散しており、どこに集中するか決めるとき
- **やり方**: 件数・金額等でソートし、上位2割で全体の8割を占める領域を特定
- **注意**: データがあるときのみ。Pythonで実際に集計する

## リスク対応型

### リスクマトリクス（影響×発生確率）
- **いつ**: 懸念事項が複数あり、対応の優先順位を付けるとき
- **やり方**: 各リスクを影響度×発生確率で3×3または5×5に配置。高×高から対策（回避/低減/移転/受容）を決める
- **注意**: 「発生した場合の検知しやすさ」も加味すると実務的

### ミニマックス／ミニマックス・リグレット
- **いつ**: 最悪ケースが許容できるかが焦点のとき（行政判断で頻出）
- **やり方**: 各案の最悪シナリオを比較し、最悪の被害が最小の案を特定。または「後悔（機会損失）」が最小の案を特定
- **注意**: 期待値最大の案と結論が割れたら、両方提示して「攻めるか守るか」の判断基準に立ち返る

## タイミング型（いつやるか）

### リアルオプション的思考
- **いつ**: 今決めるか、情報が増えるまで待つかの判断
- **やり方**: ①待つことで得られる情報は何か ②待つコスト（機会損失・鮮度低下）はいくらか ③「小さく始めて選択肢を残す」段階案は作れないか、の3点を検討
- **注意**: 「延期」は決断の放棄にもなり得る。延期を推奨するなら「いつ・何が分かったら決めるか」の再判断条件を必ず付ける

### 撤退基準の事前設定
- **いつ**: 実施に踏み切る判断のとき、セットで
- **やり方**: 「○年後に指標Xが△未満なら縮小・撤退」を事前に定義
- **注意**: 撤退基準のない新規事業はサンクコストで延命されがち。採否型の判断には原則セットで付ける

## 交渉・調整型（相手のいる話）

### ステークホルダー分析（影響力×関心）
- **いつ**: 庁内外の調整方針を決めるとき
- **やり方**: 関係者を影響力×関心の2軸に配置し、それぞれへの働きかけ方（重点管理/満足維持/情報提供/監視）と順番を決める
- **注意**: 「キーパーソンの利害・面子」を1行ずつ言語化すると精度が上がる

### BATNA / ZOPA
- **いつ**: 民間事業者・他部局・他自治体との交渉方針
- **やり方**: 自分と相手の「合意できない場合の次善策（BATNA）」を推定し、合意可能領域（ZOPA）を見積もってから譲歩ラインを決める
- **注意**: 相手のBATNAは推測にすぎないことを明記する

## 原因究明→対策型

### ロジックツリー／なぜなぜ分析
- **いつ**: 「どう対処すべきか」の前に問題の構造が曖昧なとき
- **やり方**: 問題をMECEに分解（Whyツリー）してから、対策候補を出す（Howツリー）
- **注意**: 分解して満足しない。必ず「効く枝」を特定して対策の判断につなげる

# 定量分析の道具箱

データが得られたら、目分量でなくPythonで計算する。

- **加重スコア＋感度分析**: 重みを±10〜20%振って順位の頑健性を確認。結論の確度の根拠になる
- **期待値計算**: シナリオ×確率。確率の出典または仮定を明記
- **簡易モンテカルロ**: 費用・需要に幅があるとき、一様分布や三角分布で1万回試行し、結果の分布（○○%の確率で赤字、等）を示す
- **損益分岐点**: 「利用者が年○人を超えれば黒字」の形は、行政の説明で最も通じやすい
- **統計・機械学習**: 判断がデータ分析そのものを要する場合（需要予測等）は、本格的な分析ワークフロー（policy-data-workflowスキル等）への切り出しを提案する

# バイアス確認リスト（結論の前に一瞥する）

- **確証バイアス**: 推奨案に不利な情報も探したか？
- **サンクコスト**: 「ここまでやったから」が理由に混ざっていないか？
- **現状維持バイアス**: 現状維持を選ぶ理由が「変える手間」だけになっていないか？（リバーサルテスト）
- **アンカリング**: 最初に提示された案・数字に引きずられていないか？
- **計画錯誤**: 工数・工期の見積りは類似事例の実績と比べたか？
- **同調**: 「上が言っているから」を根拠から除いても結論は同じか？

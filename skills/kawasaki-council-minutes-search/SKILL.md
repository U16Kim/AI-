# 川崎市議会 会議録検索 Skill

あいまいな日本語の指示から検索条件を組み立て、川崎市議会会議録検索システムをブラウザ操作で検索し、結果を要約するためのSkill。

## 前提条件

- Claude in Chrome（ブラウザ拡張）が接続されていること。接続されていなければ、その旨をユーザーに伝えて終了する。
- 対象サイト（詳細検索）: `https://www13.gijiroku.com/kawasaki_council/g07v_search.asp?Sflg=2`
- サイトは Shift_JIS・クラシックASPで構築されており、**検索結果はセッションに紐付くiframe内に描画される**。結果ページを直接URLで再現することはできず、毎回ブラウザでフォームを操作する必要がある（バックグラウンド実行・定期実行には使えない）。

## 全体フロー

1. あいまいな指示を検索条件に変換する（Step1）
2. 詳細検索ページを開き、条件を入力して「検索実行」を押す（Step2）
3. 結果一覧（Level1: 会議日リスト）から◆／◎アイコンで発言抜粋（Level2）を展開し、上位候補を確認する（Step3）
4. 重要と判断した上位数件は本文ページへのドリルダウンを試みる（Step4／Level3）
5. 要約して報告する（Step5）

---

## Step1: あいまい指示 → 検索条件マッピング

### キーワード抽出（検索語1〜4）
- 指示文中の固有名詞・政策用語・部署名・事業名を検索語1〜4に割り当てる（最大4つ）。
- 意味が近い語同士は「検索語をすべて含む」（AND）、話題を広く拾いたい場合は「検索語のいずれかを含む」（OR）を選ぶ。迷ったら核となる語のみ検索語1に入れ、残りはANDで絞り込む方が結果が扱いやすい。
- 同義語検索（類語展開機能）は既定「する」のままでよい。固有名詞（部署名・事業名等）は類語展開で誤ヒットが増えることがあるため、結果が的外れに広い場合は「しない」への切り替えを検討する。

### 期間の解釈
- 「最近」「直近」など曖昧な時間表現 → 既定で**直近2年間**（開始年を現在から24か月遡った値に設定、終了は空欄のまま＝現在まで）。
- 具体的な年度・年が指示にあればそのまま反映する。
- 期間の指定がない、または「過去すべて」等の指示 → 期間指定は空欄のまま（全期間＝昭和61年〜現在が対象）。

### 検索対象の会議（委員会）の絞り込み
**既定は「全委員会を対象」のまま**とする（網羅性優先。取りこぼしを避けるため）。指示文で委員会や所管が明確に指定されている場合のみ、該当委員会だけにチェックを絞る。所管の目安は以下の通り。

| 話題の所管 | 対応する委員会 |
|---|---|
| 総務企画局・共創推進室・人事・情報化・危機管理 | 総務委員会 |
| 教育・学校 | 文教委員会 |
| 戸籍・区役所・市民活動・文化 | 市民委員会 |
| 福祉・医療・こども | 健康福祉委員会 |
| 都市計画・住宅・再開発・PPP/PFI・公共空間活用・建築 | まちづくり委員会 |
| 環境・ごみ・公園緑地 | 環境委員会 |
| 予算・決算全般 | 予算・決算審査特別委員会 |
| 本会議での代表質問・一般質問 | 本会議 |

### 発言者の種別
既定＝「質問者」＋「答弁者」の両方（議論の全体像を把握するため）。「答弁だけ知りたい」等の指示があれば「答弁者」のみに絞る。

### 個人・役職の指定
- 議員名が指示にあれば「発言者名」プルダウンで該当議員を選択する（同姓同名や旧字体に注意。選択肢の表示テキストと完全一致させる）。
- 「〇〇局長の答弁」等、理事者側の役職が指示にあれば「執行部役職名」プルダウンで選択する（例: 総務企画局長＝共創推進室の答弁責任者）。

## Step2: フォーム入力の実施手順（Claude in Chrome）

1. `navigate` で `https://www13.gijiroku.com/kawasaki_council/g07v_search.asp?Sflg=2` を開く。
2. `find` で各項目のラベル文字列（例:「検索語1 input field」「検索実行 submit button」）を検索し、返ってきたrefを使う。**refはページロードのたびに変わりうるため、前回セッションのrefを使い回さない**こと。
3. テキスト欄・チェックボックス・ラジオ・プルダウンはいずれも `form_input` で値を設定できる（テキストは文字列、チェックボックスはboolean、プルダウンはoption値またはラベルテキスト）。
4. 「検索実行」ボタンは `computer` ツールの `left_click`（ref指定可）で押す。`form_input` はあくまで値設定用であり、送信操作には使わない。
5. クリック後は2〜3秒 `wait` してから状態を確認する（即座に読み取ると反映前の状態を見てしまうことがある）。

## Step3: 結果の読み取り（重要な制約）

検索結果はiframe内に描画されるため、**`read_page` や `find` では結果内の要素を検出できない**（外側の検索フォームは検出できるが、結果一覧・抜粋・リンクは不可）。結果の確認・操作は次の方法で行う。

1. `computer` の `screenshot` で結果画面を撮影する。
2. 各会議日の行の左端にある「◆」（質問者側）「◎」（答弁者側）アイコンをクリックすると、その日にキーワードを含む発言が「発言者名（役職）＋前後文脈の抜粋＋掲載ページ（例: P.35）」の形で展開される。
3. 座標クリックが必要になるため、**クリック直前に必ず最新のスクリーンショットを取得**してから座標を決める（スクロール位置やページ内容でズレるため）。位置の微調整が必要な場合は `zoom` で対象領域を拡大して確認する。

ヒット件数が多い場合（例: 単一キーワードで数百件になることがある）は、結果一覧の先頭（既定は「新しい会議から表示」＝新しい順）から順に◆を展開し、抜粋が本当に関連しているか確認しながら上位候補を絞り込む。全件を機械的に展開する必要はない。

## Step4: 本文ページへのドリルダウン（Level3・要現地確認）

**ユーザー方針（確認済み）**: 抜粋一覧の要約だけでなく、重要と判断した上位数件については本文ページまでドリルダウンして詳細を確認することを標準動作とする。

発言者名リンク（例:「委員(吉沢章子)」）をクリックすると該当ページの本文へジャンプする設計と推測されるが、本Skill作成時のテストでは新規タブ・ウィンドウの発生を確認できなかった（ポップアップブロックの可能性がある）。実行時は次の手順で確認すること。

1. リンクをクリック後、`tabs_context_mcp` で新規タブが開いていないか確認する。
2. 開いていなければポップアップブロックの可能性があるため、アドレスバー付近のブロック通知の有無をスクリーンショットで確認する。
3. それでも本文が取得できない場合は、フォールバックとして「本会議録の閲覧」（`g08v_viewh.asp`）または「特別委員会・常任委員会等記録の閲覧」（`g08v_views.asp`）から該当年月・会議名を選び、抜粋に記載されたページ番号（例: P.35）を頼りに本文を探す。
4. どうしても本文が取得できない場合は、無理に推測で補わず、抜粋（Level2）の内容と「本文は未取得」である旨を正直に報告する。

---

## Step5: 出力の作成

- 最初に平易な日本語で概略（何件ヒットし、どんな傾向か）を提示し、その後に詳細（発言者・発言日・委員会・要旨）を提示する。
- 議事録本文の引用は要約・言い換えを基本とする。逐語引用は1発言につき15語未満・1箇所までとし、複数発言から引用を重ねない。
- 発言日・委員会名・ページ番号を出典として明記する（例:「令和8年5月27日 環境委員会 P.35」）。
- 使用した検索条件（キーワード・期間・委員会絞り込みの有無・発言者属性）を末尾に明記し、ユーザーが条件を再現・修正できるようにする。
- 答弁の整理では、**約束の強さ**（実施する／取り組む／検討する／研究する／注視する）と、**答弁者の職**を必ず記録する。同じテーマの答弁を時系列に並べ、踏み込みの変化を示す。
- 検索結果は、答弁案（`exec-council-stakeholder-comms`）、例規の適用判断（`rules-research-and-subsidy-drafting`）、判断材料（`decision-support`）に渡す。横浜市会・東京都議会の会議録は、`metro-gov-reference` の入口から各議会の検索システムを使う（操作手順はこのスキルの考え方を準用し、画面の違いはその場で確認する）。

## 既知の制約（正直な弱点）

- セッションベースのASPフォームのため検索結果を直接URLで再現できない。必ずチャット内でClaude in Chromeを操作する形になり、バックグラウンド・定期実行には使えない。
- 単一キーワードでは数百件ヒットすることが多い（例:「PFI」で616件）。委員会・期間・発言者属性の組み合わせによる絞り込みがほぼ必須。
- 発言者名プルダウンには歴代議員（300名超、引退・物故者含む）が含まれる。現職かどうかは別途確認が必要。
- Level3（本文ドリルダウン）の遷移方法は本Skill作成時点で未確定。実行時に都度、上記Step4の手順で確認すること。

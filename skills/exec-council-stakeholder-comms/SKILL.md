# 議会答弁・幹部説明・合意形成

相手（議員・幹部・地元・企業）に、正確に、納得できる形で伝え、必要な判断や合意を得るための型。

## 最初にやること

| モード | 典型的な依頼 |
|---|---|
A 議会答弁案 | 「質問通告が来た」「答弁を書いて」「想定問答を作って」
B 幹部への意思決定資料・説明 | 「室長・局長に説明したい」「決裁資料を作りたい」
C 地元・企業との協議・合意形成 | 「地元に説明する」「事業者と調整する」「合意文書を作りたい」

不足情報は、まとめて1回だけ質問する（最大3項目）。

## 共通ルール

- 最初に「概略」を簡単な日本語で、次に詳細を書く。
- 数値・事実には出典を付ける。確認できないものは「要確認」と書く。
- 相手が「何を知りたいか」「何を決めたいか」から逆算して構成する。
- 約束できないことを書かない。予算、法令、他機関の判断に依存することは、条件として明記する。
- 作成後は `deliverable-verifier` で事実・数値・論理を検証する。

## モードA: 議会答弁案

### 入力
質問通告（質問文）、質問者・会派、関連する計画・予算・事業の現状、所管課の情報。

### 手順
1. **質問を分解する**
   - 表の質問（聞かれていること）と、本当に聞きたいこと（背景・意図）
   - 質問を1問ずつに分け、答弁の担当（市長・局長・室長）を仮置きする
2. **過去の答弁を調べる**: `kawasaki-council-minutes-search` で、同じ・近いテーマの過去の質疑と答弁を確認する。過去の答弁と**矛盾しない**ことを必ず確認する。踏み込みを変える場合は、理由を整理する。
3. **答弁の型で書く**
   - 現状・事実 → これまでの取組 → 課題 → 今後の方向性
   - 約束の強さを、次の表で使い分ける。強い表現は、予算・法的根拠・他機関の同意があるときだけ使う。

   | 強さ | 表現の例 | 使える条件 |
   |---|---|---|
   | 強い | 実施する、〜年度から開始する | 予算・根拠・体制が確定している |
   | やや強い | 取り組んでいく、進めていく | 方針が決まり、実施の見通しがある |
   | 中 | 検討していく、検討を進める | 実施の可否を含めて検討する。期限を聞かれる |
   | 弱い | 研究していく、調査・研究する | 当面は実施しない含み |
   | 状況次第 | 国・他都市の動向を注視する | 自らは動かない含み |

   表は一般的な目安。川崎市議会での実際の使われ方は、`kawasaki-council-minutes-search` で近い答弁を見て合わせる。
   - 法令・判例に触れる答弁は、`japan-law-research` の手順で条文と判決文を確認する。記憶で条番号や判例を書かない。
4. **数字を確認する**: すべての数値に出典と時点を付ける。
5. **想定問答（再質問）を作る**: 再質問を3〜5個想定し、答弁案と根拠資料を付ける。
6. **関係課との合議事項**を洗い出す（財政、法制、関係局）。
7. **日程を確認する**: 定例会の会期と質問通告の締切は、川崎市議会の公式サイトで確認する。質問通告の締切は未確認（要確認）。確認済みの会期: 令和7年第4回は2025-11-26〜12-22、令和8年第2回は2026-06-01〜06-24。令和8年第4回は未確認。出典は `kawasaki-admin-reference` の「議会」。

### 出力
- 答弁案（読み上げて自然な文体。です・ます調）
- 質問の意図の分析（簡潔に）
- 想定問答（質問・答弁案・根拠）
- 過去答弁との整合表
- 要確認事項リスト

### 弱点チェック
- 約束しすぎていないか。
- 質問に正面から答えているか（論点をずらしていないか）。
- 一般市民が聞いて分かる言葉か。
- 他都市の事例を聞かれたときの答えがあるか（横浜市・東京都は `metro-gov-reference` の調べ方で確認）。
- 過去の答弁より踏み込む場合、その理由と、庁内の了解があるか。

## モードB: 幹部への意思決定資料・説明

### 手順
1. **ゴールを1文で決める**: 幹部に「何をしてほしいか」（決裁・了承・方針決定・報告のみ）。
2. **構成（結論を先に）**
   1. 求めること（決裁・了承など）
   2. 背景と現状（数値で）
   3. 選択肢（2〜3案）の比較（効果・費用・リスク・実現性）
   4. 推奨案と理由
   5. 主なリスクと対応
   6. 財政影響と必要な予算措置
   7. スケジュール（今後の節目）
   8. 関係者の意見・協議状況
3. **事例**: 国内外の類似事例を1〜3件。成功と失敗の両方。
4. **想定問答**: 幹部・財政・議会・関係局から出る質問を先回りして用意する。
5. **説明の型を3つ用意する**: 30秒版（結論と依頼）、3分版（要点）、10分版（詳細）。
6. **骨格と見た目**: 先に `logic-storyline` で、Ask・結論・根拠3つ・想定される反論を設計する。見た目は `kmr-visual-deliverables` の手順（型の判定→デザイン3案）で内容から決める。本文は10.5pt以上にする。

### 出力
- 1枚の要約（A4・1枚）
- 本編資料
- 想定問答
- 説明用の台本（30秒・3分・10分）
- 要確認事項リスト

### 弱点チェック
- 結論が1ページ目で分かるか。
- 選択肢に「何もしない」「延期する」が入っているか。
- 推奨の根拠が3つ以内に絞られているか。
- 自分に都合のよい情報だけを集めていないか。

## モードC: 地元・企業との協議・合意形成

### 手順
1. **関係者マップ**を作る。

| 関係者 | 立場 | 関心・懸念 | 影響の大きさ | 現在の態度 | 目指す状態 |
|---|---|---|---|---|---|

2. **論点を分ける**: 合意すべきこと、条件付きで譲れること、譲れないこと（法令・公平性・予算の制約）。譲れない理由は、相手に説明できる言葉で書く。
3. **進め方を設計する**: 事前ヒアリング → 論点整理 → 案の提示 → 修正 → 合意文書。
4. **協議当日の準備**: 目的、ゴール、議題、時間配分、想定される反応、こちらの答え、持ち帰り事項。
5. **合意の記録**: 協議後、24時間以内を目安に議事メモを送る。決まったこと、決まっていないこと、次の担当と期限を書く。
6. **合意文書**: 内容に応じて、覚書・協定・確認書など。法的な拘束力の有無、相手の署名権限、公平性・利益相反・契約方式の確認が必要（要確認）。

### 官民連携で特に確認すること
- 特定の事業者を優遇していないか（公募・選定の透明性）。
- 公有財産・公共空間を使う場合の許可・契約の種類（`public-space-unlock` を参照）。
- 費用負担・責任分担・事故時の対応。
- 合意内容を、議会・住民に説明できるか。
- 川崎市の枠組みに沿っているか。民間活用（川崎版PPP）推進方針（令和2年3月策定。「民間」には企業だけでなくNPO・自治会等も含む）、優先的検討（ハード事業は原則対象、ソフト事業は個別検討）、官民連携総合窓口のテーマ型・フリー型提案。確認済みの内容とURLは `kawasaki-admin-reference` の「官民連携」。

### 出力
- 関係者マップ
- 論点整理表（合意・条件付き・譲れない）
- 協議の台本（議題・時間・想定反応）
- 議事メモの雛形
- 合意文書の骨子

### 弱点チェック
- 声の大きい関係者だけを見ていないか。
- 相手の「立場」ではなく「関心」を聞けているか。
- 約束した内容を、庁内で実行できる見通しがあるか。
